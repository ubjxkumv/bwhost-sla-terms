# 搬瓦工 SLA 套餐：看懂 99.99% 可用性、服务补偿和购买前要核对的限制

搜索“搬瓦工 SLA 套餐”，通常不是只想知道 SLA 是什么，而是想判断多花的钱买到了什么：可用性承诺是否等于宕机赔钱，CPU 使用有没有区别，套餐价格和配置又该怎么看。

先说结论：搬瓦工的 SLA 只适用于购买页面明确标注包含 SLA 的方案。官方条款写的是每台符合条件的 VPS 每个自然月努力达到 **99.99% 月度可用性**；如果满足条件，补偿形式是给这台 VPS 增加预付服务时长，不是现金退款，也不是对业务损失的赔偿。

这几个区别很重要。99.99% 是有范围、有排除项、需要主动申报的服务等级条款，不是“服务器永远不会断”。如果你只是搭个人网站，SLA 未必值得额外付费；如果业务需要持续高 CPU，或需要明确的供应商可用性承诺，它才更值得认真比较。

## 搬瓦工 SLA 套餐是什么

BandwagonHost（搬瓦工）的 SLA 是服务等级协议，覆盖范围不是所有 VPS。官方条款明确限定：只有套餐页面注明适用 SLA，或明确写有“Service Level Agreement”的方案，才属于 SLA Plan。普通套餐、免费或试用服务不能因为同属搬瓦工就自动获得这项保障。

购买时应以具体订单页显示为准，而不是只看第三方文章里的套餐简称。产品名称、库存、可选配置和价格可能变化；进入下单页后，先确认页面是否明确标注 SLA，再看所选配置是否仍有货。

搬瓦工 SLA 的月度可用性按单台 VPS 计算。它不会自动覆盖账户里的其他 VPS，也不等于网站、数据库、DNS 或第三方服务都有可用性保障。官方将故障定义为：由于搬瓦工网络或承载该 VPS 的物理主机问题，服务器无法通过其标准连通性检查超过连续一分钟，并且其内部系统确认故障不属于 SLA 排除情形。单纯 ping 不通、但正常 TCP 等流量仍可用，不一定会被认定为不可用。

## 99.99% SLA 实际意味着什么

99.99% 听起来很高，但最好把它看成一条合同规则，而非不间断运行的保证。官方会按日历月统计符合定义的停机时间，并排除条款列出的情形。也就是说，用户软件配置错误、遭遇 DDoS 后采取的流量限制、第三方网络故障，或 IP 被政府及第三方屏蔽等情况，可能不计入 SLA 停机时间。

补偿也不是按损失金额计算。官方 SLA 按符合条件的停机分钟数提供预付服务时长，梯度从 12 小时到一个日历月不等；每台 VPS 每月补偿上限为一个月的预付服务时长。服务额度只能加到发生故障的那台 VPS，不能转移到其他服务器，也不能兑换现金。

因此，SLA 更像是对特定服务故障提供有限的合同补偿，不是商业中断险。停机可能造成的订单损失、客户流失或数据恢复成本，并不会因为有 SLA 就自动得到赔偿。关键业务仍需要独立监控、备份和故障切换方案。

## SLA 套餐与普通 VPS 的差别

对多数人来说，实际差异主要在 SLA 资格、持续 CPU 使用规则和具体套餐页面承诺的配置。搬瓦工服务条款列出，SLA Plan 可使用全部可用 CPU 核心，24 小时不设该项上限；普通套餐则按不同方案设置 CPU 使用限制。

这不代表所有任务都能无限跑满 CPU。磁盘 I/O、资源公平使用政策、服务条款以及应用本身的瓶颈仍然存在。官方 SLA 也将按套餐或公平使用规则施加的资源限制列入排除情形。买之前最好结合自己的负载看，而不是只盯着“核心数”或“SLA”几个字。

| 比较项目 | SLA 套餐 | 普通搬瓦工 VPS |
| --- | --- | --- |
| SLA 适用范围 | 仅限页面明确标注 SLA 的方案 | 默认不适用 SLA，除非订单页明确说明 |
| 可用性规则 | 官方条款列出每月 99.99% 目标及申请服务补偿的条件 | 不享有该 SLA 的服务补偿条款 |
| CPU 使用规则 | 官方条款列出全部可用核心 24/7、不设该项上限 | 按具体套餐规定 CPU 使用限制 |

| 故障排除项 | 有维护、用户配置、攻击、第三方网络等排除情形 | SLA 条款不覆盖 |

如果你的用途是轻量博客、测试环境或偶尔运行的小工具，先确认普通方案的 CPU、内存、存储和网络是否够用，通常比为 SLA 付费更直接。反过来，如果任务长期占用 CPU，或需要在供应商协议中明确可用性处理方式，SLA 的价值就不只是一个百分比。

## 申请 SLA 补偿时要做什么

如果怀疑 VPS 的故障符合 SLA，单独提交普通客服工单并不够。条款要求明确申请“SLA Service Credit”，指出受影响的 VPS，并提供大致故障时间、对使用造成的影响，以及可用的监控截图、日志或网络诊断信息。申请期限是故障所在日历月结束后 90 天内，超期会失去该月申请服务补偿的资格。

实用做法是提前准备外部监控记录，而不是等故障结束后才回忆时间点。可以保留多个网络探测点的连通性结果、应用日志和故障开始与恢复时间。官方监控记录仍是主要判断依据，但用户资料有助于说明故障情况。

同时要判断问题是否真的属于服务端或其网络。如果只是网站进程崩溃、系统防火墙误配置、DNS 设置错误或应用升级失败，即使访问者看到网站打不开，也未必满足 SLA 中的不可用定义。条款还明确排除了用户软件、数据和配置导致的问题。

## 哪些人适合选择 SLA 套餐

SLA 更适合对持续运行和 CPU 使用有明确需求的人，而不是所有 VPS 用户都该选的“高配版”。

可以优先考虑 SLA 的情形：

- 服务器承载持续计算、编译或其他长期 CPU 负载，并且具体订单页的资源配置符合需求。
- 业务内部有可用性要求，需要供应商书面说明故障定义、例外情况和补偿流程。
- 你能接受服务补偿仅为额外预付时长，且愿意自行监控、保存证据并按期限申报。
- SLA 套餐实际提供的地点、网络和硬件配置适合你的项目。

如果只是学习 Linux、跑低流量网站或做短期开发测试，先比较普通套餐是否足够。SLA 不会替你修复应用，也不会自动处理数据备份、数据库复制或 DNS 切换。为这些问题付 SLA 溢价，往往买错了保障对象。

还要留意 SLA 的适用范围：若用户需要香港、日本、新加坡等特定地域，应先确认所选 SLA 产品是否有对应机房。不能把某个 SLA 方案的地点和线路特点，默认套用到搬瓦工所有系列。

## 购买前的核对清单

结账前花几分钟逐项看清楚，通常比购买后才发现产品与预期不同更省事：

1. **订单页是否明确标注 SLA。** 产品系列名称或第三方简称不能代替订单条款。
2. **套餐配置和地点是否匹配。** 核对 CPU、内存、存储、流量、端口及数据中心。
3. **价格对应什么周期。** 区分首次费用、续费金额和付款周期，检查结算页是否有附加项。
4. **补偿是否符合你的预期。** SLA 服务补偿是 VPS 预付时长，不是退款或损失赔偿。
5. **故障是否可能被排除。** 用户配置、攻击、维护、上游网络和第三方封锁等都可能不计入。
6. **你是否有监控证据。** 申请要主动提交，且需在期限内明确提出 SLA Service Credit。
7. **业务是否需要额外容灾。** 单台 VPS 的 SLA 不等于异地备份、双机热备或应用级可用性。

## 常见问题

### 搬瓦工所有套餐都包含 SLA 吗？

不是。官方条款限定只有明确标注 SLA 的方案适用，其他套餐不自动获得 SLA 覆盖。下单前应以具体产品页面为准。

### 99.99% 是保证服务器永远在线吗？

不是。官方把它定义为每个日历月的可用性目标，并设有故障定义和排除项。即使达到申请条件，服务补偿也有上限，且不会变成现金退款。

### SLA 套餐宕机后会自动补偿吗？

不会。需要通过客服渠道提交申请，明确要求 SLA Service Credit，并提供受影响服务和故障时间等信息。申请须在故障所在月份结束后的 90 天内收到。

### 有 SLA 还需要自己做备份吗？

需要。SLA 处理的是特定服务不可用情况下的服务补偿，不等于数据备份或灾难恢复方案。重要数据仍应独立备份，并根据业务需要准备监控、恢复流程或备用节点。

## 结论：先看你要解决的问题，再为 SLA 付费

搬瓦工 SLA 套餐的核心价值可以概括为两点：针对明确标注 SLA 的 VPS 提供 99.99% 月度可用性条款，以及在符合条件时按规则增加服务时长；官方服务条款还列出 SLA Plan 可持续使用全部可用 CPU 核心。

它不提供现金赔偿，也不覆盖所有网站故障、网络路径问题或攻击事件。若你的重点是稳定运营，除了比较 SLA，还要确认机房、硬件配置、续费价格和自己的容灾能力。若只是轻量使用，先判断普通 VPS 是否足够，再决定是否需要为这份合同保障增加预算。
